# 저장소 통합 설계 — 파일·노트 일원화

작성일: 2026-08-17 · 대규모 개편 2단계

## 문제

지금은 한 사용자의 문서가 세 곳에 흩어져 있다.

| 공간 | 경로 | 진입 UI |
|---|---|---|
| 공통 | `STORAGE_ROOT/common` | 파일 페이지 · 노트 페이지 |
| 개인 파일 | `users/<u>/files` | 파일 페이지 · 노트 페이지 |
| 개인 노트 | `users/<u>/notes` | 노트 페이지 |

같은 문서를 두 페이지에서 다르게 보게 되고, 노트 페이지의 소스 셀렉터는
`base(notes|files) × scope(me|common)` 4조합을 강요한다. 사용자가 "따로 분리되어
있어 불편하다"고 지적한 지점이다.

## 목표

- 개인 문서 공간을 **하나로 통합**한다
- **파일 페이지를 없애고** 노트 페이지에서 모든 파일을 다룬다
- 노트 페이지에서 **PDF·이미지 등도 열람**한다 (가능한 최대 범위)
- 파일 생성 기본 확장자는 **마크다운 유지**
- 무조건 열린 `common` 공간을 **삭제**한다 (허가 기반 공유는 3단계에서 재구축)

## 저장소 모델

```
STORAGE_ROOT/
  users/<username>/
    data/          ← 사용자 문서 전부 (기존 files/ + notes/ 병합)
    calendar/      ← 시스템 데이터 (변경 없음)
    ai/logs/       ← 시스템 데이터 (변경 없음)
    .trash/        ← 휴지통 (변경 없음)
```

`common/`은 제거한다. 실측 결과 **파일 0개**라 삭제에 위험이 없다.

`scope` 매개변수를 **API 표면에서 완전히 제거**한다. 값이 하나뿐인 매개변수를
남겨두면 호출자가 계속 신경 써야 하고, 이번 개편의 목적 자체가 그 복잡도를
없애는 것이다.

### 데이터 이전

실측: `files/` 102개, `notes/` 37개, **최상위 이름 충돌 없음**, `common/` 0개.

```
users/<u>/notes/*  →  users/<u>/data/
users/<u>/files/*  →  users/<u>/data/
```

충돌이 생기면 이전을 중단하고 보고한다(자동 리네임하지 않는다 — 사용자 문서를
말없이 바꾸지 않기 위해). 원본은 검증 전까지 보존한다.

## 파일 종류별 처리

노트 페이지가 확장자로 판단해 뷰어를 고른다. **새 의존성 없이** 브라우저 기본
기능만 쓴다.

| 종류 | 확장자 | 처리 |
|---|---|---|
| 마크다운 | `.md`, `.markdown` | 라이브 프리뷰 에디터(현행) + 읽기 뷰 |
| 텍스트·코드 | `.txt`, `.json`, `.py`, `.ts`, `.js`, `.css`, `.html`, `.yml`, `.sh`, `.sql` 등 | CodeMirror 편집 |
| 이미지 | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.bmp`, `.avif` | `<img>` 뷰어 (확대/원본 열기) |
| PDF | `.pdf` | `<iframe>` 브라우저 내장 뷰어 |
| 비디오 | `.mp4`, `.webm`, `.ogv` | `<video controls>` |
| 오디오 | `.mp3`, `.wav`, `.ogg`, `.m4a`, `.flac` | `<audio controls>` |
| 그 외 | | 다운로드 버튼 + 크기 표시 |

편집 가능한 것은 텍스트 계열뿐이다. 나머지는 읽기 전용이며 자동저장 대상이 아니다.

**파일 생성**: 확장자를 안 적으면 `.md`를 붙인다(현행 유지).

## API 변경

### 제거

- `/api/files/*` 라우터 전체 — 노트 라우터로 흡수
- 모든 엔드포인트의 `scope` 쿼리 파라미터
- 노트 라우터의 `base` 파라미터 (`notes`/`files` 구분이 사라짐)

### 노트 라우터로 흡수

| 기존 | 신규 |
|---|---|
| `GET /api/files/list` | `GET /api/notes/tree` (모든 파일 포함) |
| `GET /api/files/download` | `GET /api/notes/raw?path=` |
| `POST /api/files/upload` | `POST /api/notes/upload` |
| `POST /api/files/mkdir` | `POST /api/notes/folder` (기존) |
| `POST /api/files/rename` | `POST /api/notes/rename` (기존) |
| `DELETE /api/files/delete` | `DELETE /api/notes/delete` (기존) |

`tree`는 이제 `.md`만이 아니라 **모든 파일**을 돌려주며, 각 항목에 `kind`
(`md|text|image|pdf|video|audio|other`)와 `size`를 담아 프런트가 뷰어를 고를 수
있게 한다.

## 프런트 변경

**삭제**: `pages/Files.tsx`, `components/files/FileExplorer.tsx`,
`components/files/FileViewer.tsx`, `/files` 라우트, 사이드바 "파일" 항목,
대시보드 "파일" 카드.

**노트 페이지**: 소스 셀렉터가 사라진다(공간이 하나뿐). 트리는 모든 파일을 보여주고,
선택한 파일의 종류에 따라 우측 패널이 에디터/이미지/PDF/미디어/다운로드로 바뀐다.
업로드 버튼과 드래그&드롭 업로드를 노트 페이지에 추가한다.

**그래프**: 소스 토글(공통/내 노트) 제거 — 개인 공간 하나만 남는다.

**연동(Sync)·설정**: `scope` 선택 UI 제거.

## AI 스킬 변경

`scope` 인자를 모든 파일·노트 스킬에서 제거한다. `_SCOPE_PROP` 삭제.
[[ai-skill-contracts]]의 노트 식별자 규약(`폴더/제목`)은 그대로 유지하되,
이제 확장자가 있는 파일도 다루므로 식별자는 **확장자를 포함한 상대경로**로
통일한다(`.md`는 생략 허용 — 기존 동작 호환).

## 순서

1. 백엔드 저장소 모델 (`storage.py`, `config.py`) + 이전 스크립트
2. 노트 라우터 확장 (모든 파일 종류, upload/raw), 파일 라우터 삭제
3. AI 스킬에서 scope 제거
4. 트래시·동기화 정리
5. 프런트: 노트 페이지 통합 뷰어 → 파일 페이지 삭제 → 그래프/설정/연동 정리
6. 서버 데이터 이전 후 배포

각 단계마다 테스트를 통과시킨 뒤 다음으로 넘어간다.

## 검증

- `test_smoke` 전체 통과 (scope 관련 테스트는 새 모델로 재작성)
- 노트 페이지에서 `.md` 편집, `.png` 표시, `.pdf` 표시, 기타 다운로드 확인
- 이전 후 파일 수 대조: `files 102 + notes 37 = data 139`
- 배포 후 실제 브라우저 확인

## 위험

- **되돌리기 어려운 데이터 이동**이다. 원본(`files/`, `notes/`)을 지우지 않고
  복사한 뒤 검증하며, 서버의 `/mnt/hdd/server` 백업도 그대로 둔다.
- 로컬 연동(Sync) 클라이언트가 `scope`를 쓰고 있어, 기존 매니페스트는 재설정이
  필요하다. 브라우저 IndexedDB에 저장되므로 사용자가 폴더를 다시 연결해야 한다.
