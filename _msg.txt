perf+refactor: 트리 순회를 scandir로, 미사용 코드 제거

순회 방식 교체(가장 큰 이득). Path.rglob 은 항목마다 Path 를 만들고
is_file()·stat() 에서 파일시스템을 각각 다시 두드린다. os.scandir 은
디렉터리를 읽을 때 이미 받아 둔 정보를 그대로 준다.
실측(파일 200개): rglob 78ms -> scandir 3.1ms.

storage.walk_files/walk_dirs 로 한 곳에 모으고 전부 교체했다.
엔드포인트·스킬 실측(문서 200 · 할 일 300 · 일정 200):
  list_documents       114ms -> 13ms   (8.8배)
  GET /api/notes/tree   97ms -> 22ms
  GET /api/notes/list   66ms -> 21ms
  GET /api/notes/graph  49ms -> 32ms
  search_documents      32ms -> 26ms

그 밖의 저장소 최적화:
- _ident 가 마크다운 파일마다 exists() 스탯을 했다(200개면 200회, 28ms).
  이미 순회 중인 쪽은 알고 있는 경로 집합을 넘겨 스탯 0회로.
- 할 일 화면 최초 로드가 categories·list·counts 를 따로 불러 같은 파일을
  3번 읽었다 -> GET /api/todo/board 하나로(파일 1회).
- AI 스킬도 같은 이유로 board() 를 쓴다. list_todos 8.4 -> 5.7ms.
- 할 일 목록의 카테고리 경로를 줄마다 계산하며 매번 색인을 새로 만들었다
  (O(n·m)) -> _path_map 으로 한 번에.
- todo_store 의 정렬·집계 중복을 _sorted/_counts_of 로 합쳤다.

미사용 코드 제거(정의만 있고 부르는 곳이 없던 것):
  backend: schemas 4개 + FileEntry, config.find_user, notes_graph._iter_notes,
           datetimes.parse_date_only, todo._cat_name, auth.verify_token
  frontend: format.ts 의 formatTime·fileKind·isTextFile(+확장자 표 2개 —
           backend/file_kinds.py 와 중복된 두 번째 출처였다), api.FileEntry
  package.json: codemirror 메타 패키지(개별 하위 패키지만 쓴다)
