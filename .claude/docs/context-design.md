# 대화 컨텍스트 설계

작성 2026-09-06. 이 문서는 **왜 이렇게 만들었는지**를 남긴다. 코드가 무엇을 하는지는
`backend/context_store.py`, `backend/ai/skills/context.py`, `frontend/src/pages/Context.tsx`
의 주석에 있다.

## 문제

화면마다 AI 가 있는데 기억이 제각각이었다.

| 화면 | 예전 |
|---|---|
| 비서(`/assistant`) | 서버에 **아무것도 남지 않음**. 브라우저가 말풍선을 매 요청 다시 보냄 |
| 캘린더 오른쪽 패널 | 위와 같음 |
| 영어 학습 | `chats/english.json` 에 남음 |
| 논문 | `papers/<id>/chat.json` 에 남음 |
| 회의 | `meetings/<id>/chat.json` 에 남음 |

남는 곳조차 모델에 들어가는 것은 "최근 20턴·24000자"뿐이었다. **어제 무슨 이야기를
했는지 물어볼 방법이 없었고**, 다른 화면에서 한 이야기는 아예 닿을 수 없었다.
스킬을 무엇을 왜 불렀는지도 300자 요약 한 줄만 남아, 나중에 "AI 가 뭘 했지"를 되짚을
수 없었다.

## 남의 것을 먼저 봤다

| 프로젝트 | 가져온 것 | 안 가져온 것 |
|---|---|---|
| [Letta(MemGPT)](https://github.com/letta-ai/letta) | **2단 기억** — 늘 프롬프트에 있는 최근 기억 + 도구로 꺼내는 보관 기억 | Postgres 상주 런타임, 자기수정 메모리 블록 |
| [Zep/Graphiti](https://github.com/getzep/graphiti) | **시간 범위 검색** — 모든 사실에 시각이 있고 "언제부터"로 자른다 | 지식 그래프, 엔티티 추출, 벡터 DB |
| [Mem0](https://github.com/mem0ai/mem0) | **범위(scope)로 나눈 기억** — user/session/agent 별 분리 | 임베딩 저장소, 요약 파이프라인 |
| Anthropic context engineering | **just-in-time 검색** — 가벼운 식별자만 들고 있다가 필요할 때 도구로 당겨 온다 | — |

**그대로 쓰지 않은 이유.** 셋 다 벡터 DB(그리고 Zep 은 그래프 DB)를 깔아야 한다.
이 서버는 라즈베리파이 5 에서 도커로 돌고 저장소는 JSON 파일이다. 임베딩을 만들려면
매 메시지마다 외부 API 를 한 번 더 태워야 하고(요금·지연), 파이에 벡터 DB 를 하나 더
띄우면 메모리가 모자란다. 대화량도 사용자 한 명 기준 하루 수십 건이라 **키워드 검색으로
충분하다** — 후보가 수백 건이지 수백만 건이 아니다.

그래서 **설계만 빌리고 구현은 이 서버 크기에 맞췄다.**

## 구조

```
                  ┌─ 최근 창(기본 24시간) ── 늘 프롬프트에 들어간다
컨텍스트 ─────────┤
                  └─ 보관분(그 이전 전부) ── AI 가 스킬로 직접 꺼낸다
                       list_context_spaces → 어디에 무엇이 있나
                       search_context      → 무슨 이야기였나 (키워드)
                       read_context        → 그 대목을 통째로
```

### 공간(space)

화면 하나 = 공간 하나. 사용자가 "어느 페이지의 컨텍스트인지"로 생각하는 단위와 같다.

| space | 파일 |
|---|---|
| `assistant` | `chats/assistant.json` |
| `calendar` | `chats/calendar.json` |
| `english` | `chats/english.json` |
| `paper:<id>` | `papers/<id>/chat.json` |
| `meeting:<id>` | `meetings/<id>/chat.json` |

논문·회의 대화가 그 폴더 안에 있는 것은 의도다 — 논문을 지우면 대화도 휴지통에 함께
가고, 복원하면 함께 돌아온다.

### 세션

파일은 여전히 **하나의 append-only 목록**이다. 세션은 저장할 때 정하지 않고 **읽을 때
시간 간격으로 나눈다**(`SESSION_GAP_SEC = 30분`).

세션 id 를 따로 적지 않는 이유: 적어 두면 서버가 재시작되거나 브라우저 탭이 여럿일 때
경계가 어긋난다. 간격으로 나누면 언제 다시 계산해도 같은 답이 나오고, 예전 기록에도
소급된다. 세션 id 는 그 세션 첫 메시지의 시각에서 만든다(`s-<unix초>`) — 안정적이고
사람이 읽을 수 있다.

### 최근 창이 "1일"인 이유

사용자가 정한 값이다. 하루면 "아까 그거", "오늘 아침에 말한" 이 대부분 걸린다.
그보다 오래된 것은 **AI 가 필요하다고 판단할 때만** 꺼내는 편이 낫다 —
프롬프트에 다 넣으면 요금과 지연이 늘고, 관계없는 옛 대화가 답을 흐린다
(Anthropic 이 말하는 just-in-time 검색).

창은 시간·턴 수·글자 수 **셋 다**로 자른다. 하루 안에 장문 대화를 몰아서 하면
시간만으로는 프롬프트가 터진다.

```
RECENT_WINDOW_SEC = 86400   # 기본 1일
MAX_HISTORY_TURNS = 20      # 그 안에서도 최근 20턴
MAX_HISTORY_CHARS = 24000
```

### 스킬 기록

메시지 meta 에 스킬 호출을 **인자와 결과까지** 남긴다. 예전에는 이름·성공여부·300자
요약뿐이라 "AI 가 무엇을 근거로 그렇게 답했는지"를 되짚을 수 없었다.

```json
{"tools": [{"name": "list_vocab", "ok": true, "message": "단어 12개",
            "args": {"tag": "Attention Is All You Need"},
            "result": "{\"items\": [...]}"}]}
```

`args`·`result` 는 각각 상한(`MAX_TOOL_ARGS`/`MAX_TOOL_RESULT`)까지만 자른다. 잘렸으면
`truncated: true` 가 붙는다 — 화면이 "잘림"이라고 표시할 수 있어야 사용자가 원문을
다 본 것으로 오해하지 않는다.

## 화면

`/context` 는 왼쪽에 **공간 폴더 → 세션 목록**, 오른쪽에 그 세션의 대화가 나온다.
스킬 호출은 접혀 있고 펼치면 인자와 결과 원문이 보인다. 목적은 감사(audit)다 —
"AI 가 내 단어장에 뭘 넣었지"를 사용자가 직접 확인할 수 있어야 한다.

## 실제로 돌려 보고 고친 것 (1차 검증)

설계대로 만든 뒤 로컬 서버에 진짜 질문을 던져 봤다. 세 가지가 깨졌고, 셋 다 **모델이
막다른 길에서 단정해 버리는** 문제였다.

| 증상 | 원인 | 고친 방법 |
|---|---|---|
| "아까 뭘 보여 달라고 했지" → "그런 대화가 없습니다" | 검색이 **모든 낱말**을 요구했다. 모델은 문장으로 검색어를 넘긴다 | 든 낱말 수로 **점수를 매겨** 순위로 가른다. 0건 절벽이 사라졌다 |
| "영어 학습 화면에서 뭐 물어봤지" → 스킬 실패 | 모델이 `space="영어 학습"`(한국어 이름)을 넘겼는데 404 | `resolve_space` 가 한국어 이름·논문 제목까지 받아 준다. 못 알아들으면 **쓸 수 있는 이름을 실패 메시지에 담아** 돌려준다 |
| 검색 0건 → 위 대화에 답이 있는데도 "없다" | 모델이 도구 결과를 자기 맥락보다 믿는다 | 0건이면 **그 공간의 최근 대화 8개를 함께** 돌려준다(막다른 길 대신 자료). 프롬프트에도 "0건이라고 단정하지 말고 위 대화를 먼저 보라"를 넣었다 |

**한 가지 더 배운 것.** 같은 질문을 반복해서 던지면, 앞선 "찾지 못했습니다" 답변이 최근
창에 쌓여 모델이 그걸 흉내 낸다. 깨끗한 공간에서는 4회 중 4회 맞혔다. 대화 기록이
프롬프트에 들어가는 이상 **틀린 답도 맥락이 된다** — 이래서 요약(compaction)보다 원문
보존이 낫다는 판단이 더 굳었다. 잘못된 답은 사용자가 컨텍스트 화면에서 지울 수 있다
(말풍선 옆 휴지통 — 지우면 다음 대화의 맥락에서도 빠진다).

## 잘렸다는 사실을 알린다 (27차 검증)

대화가 32턴이 되자 새로운 결함이 드러났다. 창은 최근 20턴만 담는데, 모델은 **보이는
앞부분을 대화의 시작으로 단정했다** — "맨 처음에 뭐라고 했지?"에 창의 첫 줄(잡담)을
그대로 답했고, 창 밖의 사실은 "그런 이야기가 없다"고 했다. 스킬을 부를 생각조차 안 했다.

시스템 프롬프트 끝에 안내를 넣는 것만으로는 부족했다. 앞서 넣은 "위 대화에 있으면
스킬을 부르지 말고 그대로 답하라"는 규칙과 부딪혀, 모델은 창 안에서 찾은 것으로 만족했다.

그래서 **대화 맨 앞에도 같은 표식을 세운다** — 모델이 '시작'을 찾는 바로 그 자리다.

```
[대화 기록 안내] 아래 대화는 이 화면('비서')의 최근 20턴뿐이고, 그 앞에 12턴이 더
있습니다. 아래 첫 줄은 대화의 시작이 아닙니다. '처음에', '아까', '지난번에' 같은
물음에는 아래만 보고 답하지 말고 read_context(space="assistant") 로 앞부분을 꺼내
확인한 뒤 답하세요.
```

오염 없는 기록으로 다시 재니 3회 중 3회 스스로 `search_context`/`read_context` 를 불러
맞혔다. **모델에게 "네가 보는 것이 전부가 아니다"를 알려 주는 것만으로 도구를 쓴다.**

## 자르는 일은 글자 수가 맡는다 (60차 검증)

27차의 안내문을 넣고도 **더 나쁜 결함이 남아 있었다.** 짧은 말 34개를 주고받은 뒤
"제일 좋아하는 음식이 뭐라고 했지?"라고 물으니 말한 적 없는 **'피자'**라고 답했다.
"화요일마다 뭘 한다고 했지?"에는 '요가'. 지어낸 것이다.

원인은 모델이 아니라 창이었다. **턴 수 상한(20)이 글자 예산(24000자)보다 먼저 걸려,
251자짜리 대화가 잘려 있었다.** 글자 예산의 1%만 쓰고 앞의 사실 세 개가 통째로 밀려난
것이다. 짧은 말이 오가는 대화일수록 손해가 크다.

- 잘림 안내를 강화하는 것만으로는 **두 번 다 못 고쳤다.**
- 턴 상한을 80으로 올려 **글자 수가 자르게** 하니 세 사실 모두 되살아났다.

프롬프트로 두 번 실패하면 구조로 옮긴다 — 이 저장소가 30·47·71차에서도 같은 결론에
닿았다. 지금은 잘림 안내에 "'…라고 했지?' 같은 물음은 낱말이 '처음에·아까'가 아니어도
지난 대화를 묻는 것이니 `read_context` 로 찾아보고, 못 찾으면 지어내지 말고 못 찾았다고
말하라"까지 적어 두었지만, 실제로 고친 것은 창을 넓힌 쪽이다.

## 하지 않은 것

- **요약/압축(compaction).** 대화량이 그만큼 크지 않다. 요약은 원문을 잃어버리는데,
  이 화면의 목적(감사)과 정면으로 부딪힌다. 나중에 대화가 수천 건이 되면 그때 넣는다.
- **임베딩 검색.** 위에 적은 이유. 키워드로 못 찾는 경우가 잦아지면 그때 다시 본다.
- **공간을 넘나드는 자동 주입.** 논문 대화에 영어 학습 대화를 자동으로 섞지 않는다.
  필요하면 AI 가 `search_context(space=...)` 로 직접 가져온다 — 무엇을 왜 가져왔는지
  스킬 칩으로 드러나는 편이 낫다.
