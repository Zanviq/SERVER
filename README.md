# TwoMES Home Server

라즈베리파이 5에서 도커로 돌아가는 개인용 멀티유저 홈서버. 문서, 캘린더(일정·기록),
할 일, 휴지통, AI 비서, 영어 학습(단어장), 논문 읽기 공간, 회의 녹음 공간을 하나의
FastAPI + React 앱으로 묶었다. 기성 솔루션 없이 직접 구현했다.

계정마다 저장소가 완전히 분리된다. 공유 공간은 없고, 모든 API는 로그인 세션을 요구하며
경로는 언제나 그 사용자의 폴더 안에서만 풀린다.

```
브라우저 (React SPA)
    |  세션 쿠키, /api
nginx  --------------------------------> terminal 컨테이너 (선택)
    |
FastAPI
    ├ auth       로그인, 세션 발급/검증, 시도 제한
    ├ notes      문서 트리, 위키링크, 그래프
    ├ calendar   내부 저장 또는 Google Calendar
    ├ diary      날짜별 상태(육체/마음/정신)와 일기
    ├ todo       할 일과 카테고리
    ├ vocab      단어장 (태그, 간격 반복 복습)
    ├ papers     논문 PDF 업로드, 백그라운드 정보 추출
    ├ meetings   회의 녹음 업로드, 백그라운드 받아쓰기(화자 구분), 정리 문서
    ├ trash      휴지통 (문서/일정/할 일/단어/논문/회의)
    ├ settings   개인 설정
    ├ admin      가입 승인, 계정 관리 (주인 전용)
    ├ system     CPU/메모리/온도/디스크, 외부 SSH 안내 (주인 전용)
    └ ai         Gemini ReAct 오케스트레이터 + 스킬 52개, 화면별 모드
    |
STORAGE_ROOT
    accounts.json
    users/<아이디>/{data, calendar, diary, todo, vocab, papers, meetings, chats, .trash, settings.json, google.json}
    deleted-users/
```

## 실행하기

### 로컬 개발

```bash
cp .env.example .env
# .env 에서 AUTH_USERS, SESSION_SECRET, STORAGE_ROOT 를 채운다

python -m venv .venv
.venv\Scripts\activate            # 리눅스/맥: source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload  # http://localhost:8000

cd frontend
npm install
npm run dev                        # http://localhost:5173
```

프런트 개발 서버가 `/api` 요청을 `localhost:8000`으로 넘긴다.
다른 주소를 쓰려면 `VITE_API_TARGET`을 설정한다.

로컬에서는 `STORAGE_ROOT=./data` 처럼 저장소를 프로젝트 안에 두면 편하다.

### 도커 (라즈베리파이)

```bash
cp .env.example .env               # 값 채우기
docker compose up -d --build       # backend + frontend
```

프로필로 선택 기능을 켠다.

| 프로필 | 켜지는 것 |
|---|---|
| `--profile tunnel` | Cloudflare Tunnel (외부 접속). `CF_TUNNEL_TOKEN` 필요 |
| `--profile terminal` | 웹 터미널 컨테이너. `ENABLE_TERMINAL=true` 도 함께 필요 |

데이터는 호스트의 `/mnt/server`에 두고 컨테이너에 그대로 마운트한다. 외장하드를 쓴다면
NTFS 위에 직접 두지 말고 ext4 loop 이미지를 올려 마운트한다 — NTFS는 `os.replace`의
원자성이 보장되지 않아 저장 도중 파일이 잠깐 사라지고, 그 순간 읽기가 빈 값을 받아
문서나 일정이 유실될 수 있다(실측 300회 중 38회).

```bash
sudo truncate -s 200G /mnt/HDD/server/server.img
sudo mkfs.ext4 -F -m 0 -L SERVERDATA /mnt/HDD/server/server.img
# /etc/fstab 에 추가
# /mnt/HDD/server/server.img /mnt/server ext4 loop,noatime,nofail,x-systemd.requires=/mnt/HDD 0 0
sudo mount /mnt/server
```

### 테스트

```bash
python -m pytest backend/test_smoke.py -q   # 백엔드
cd frontend && npm test                     # 프런트 (표, 살균, 위키링크, 자동저장 등)
```

## 환경변수

`.env.example`을 복사해서 쓴다. 굵은 것만 채우면 일단 돈다.

### 반드시 설정

| 변수 | 설명 |
|---|---|
| `SESSION_SECRET` | 세션 토큰 서명 키. 길고 무작위로. 비어 있으면 로그인이 503으로 거부된다 |
| `AUTH_USERS` | 최초 주인 계정. `[{"username":"me","password":"...","display_name":"나"}]` 형식 |
| `STORAGE_ROOT` | 데이터 루트. 파이는 `/mnt/server`, 로컬은 `./data` |

`AUTH_USERS`는 **`accounts.json`이 아예 없을 때 한 번만** 쓰인다. 이관된 뒤에는 계정의
단일 출처가 `accounts.json`이고, 여기 값을 바꿔 재시작해도 무시된다. 계정 추가는 웹에서
가입 신청 후 주인이 승인하는 방식이다.

### 자주 쓰는 것

| 변수 | 기본값 | 설명 |
|---|---|---|
| `TZ` | `Asia/Seoul` | 컨테이너 시계. 저장되는 시각이 전부 한국 시간이라 이게 어긋나면 AI의 "오늘"과 알림이 밀린다 |
| `SESSION_TTL_SECONDS` | `3600` | 폴백 값. 실제 세션 길이는 계정별 설정(기본 60분)이 정하므로 이 값을 바꿔도 로그인 세션은 달라지지 않는다 |
| `COOKIE_SECURE` | `false` | `true`면 쿠키를 HTTPS에서만 보낸다. LAN의 http 접속을 병행하면 `false` |
| `CORS_ORIGINS` | `localhost:5173,4173` | 허용 오리진. 쿠키를 쓰므로 `*` 불가 |
| `GEMINI_API_KEY` | (없음) | AI 비서·영어 튜터·논문 정보 추출·회의 받아쓰기용. 없으면 AI 대화와 추출·받아쓰기만 꺼지고 나머지는 정상 동작 |
| `GEMINI_MODEL` | `gemini-2.5-flash` | 서버 기본 모델. 계정별로 설정 화면에서 바꿀 수 있다 |
| `DEBUG` | `false` | 오류 응답에 상세를 노출할지 |
| `MAX_UPLOAD_BYTES` | `2147483648` | 업로드 1건 최대 크기 (2GB) |

### 선택 기능

| 변수 | 설명 |
|---|---|
| `CF_TUNNEL_TOKEN` | Cloudflare Tunnel 토큰. `--profile tunnel`과 함께 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` | Google Calendar 웹 OAuth. 설정하면 설정 화면에 연동 버튼이 생긴다 |
| `ENABLE_TERMINAL` | 웹 터미널 노출 여부. 기본 `false` |
| `TERMINAL_ADMINS` | 터미널을 쓸 수 있는 계정 이름 (콤마 구분) |
| `TERMINAL_ORIGINS` | 터미널 웹소켓 허용 오리진. 비우면 요청 Host와 같은 출처만 |
| `SSH_PUBLIC_HOSTNAME` | Cloudflare Tunnel 로 내보낸 SSH 호스트 이름(`ssh.example.com`). 적으면 대시보드에 클라이언트 설정이 뜬다 |
| `SSH_USER` | 위 안내에 넣을 파이 계정 이름 |

`.env`는 프로세스마다 한 번만 읽는다. 값을 바꿨으면 컨테이너를 다시 띄워야 한다.

## 기능이 어떻게 작동하는가

### 로그인과 계정

로그인에 성공하면 서버가 서명한 토큰이 `server_session` HttpOnly 쿠키로 내려간다.
토큰은 암호화가 아니라 **서명**이라 내용(`{"u": 아이디, "ttl": 초}`)은 읽을 수 있지만
위조는 안 된다. 이후 모든 보호 API는 이 쿠키만 본다.

만료는 발급 시각 기준의 절대 시간이다. 쓰고 있어도 늘어나지 않고, 어떤 요청도 쿠키를
다시 발급하지 않는다. 세션 길이는 계정별 설정(기본 60분)에서 오며 바꿔도 **다음
로그인부터** 적용된다.

세션이 들고 다니는 것은 아이디뿐이다. 역할과 상태는 요청마다 `accounts.json`에서 다시
읽으므로, 계정을 비활성화하거나 강등하면 이미 로그인한 사람에게도 즉시 반영된다.

가입은 로그인 없이 신청할 수 있지만 **주인이 승인해야** 로그인된다. 아이디는 소문자로
저장되고 조회는 대소문자를 가리지 않는다. 비밀번호는 PBKDF2-HMAC-SHA256 60만 회로
해시해 저장하며, 없는 아이디로 로그인해도 더미 해시를 한 번 계산해서 응답 시간으로
아이디 존재 여부가 새지 않게 한다.

계정에는 역할(`admin`/`user`)과 별개로 **origin**이 붙는다. `.env`로 만들어진 계정은
`bootstrap`, 웹 가입은 `signup`이다. **주인 = origin이 bootstrap이면서 role이 admin**인
계정이며, 관리 화면·시스템 상태·Google 연동·웹 터미널은 전부 주인 전용이다. 가입 계정을
admin으로 올려도 이 경로들은 열리지 않는다.

로그인 시도 제한은 **아이디 + 보낸 사람의 IP** 쌍으로 센다. 5회까지는 401이고 6번째부터
429로 막히며, 첫 잠금 30초에서 시작해 잠글 때마다 두 배씩 최대 10분이다. 잠긴 동안에도
잠금당 한 번은 비밀번호를 확인해 줘서, 오타를 낸 본인이 30초를 꼬박 기다리지 않아도 된다.
IP를 함께 세기 때문에 아이디만 아는 사람이 남을 잠글 수 없다. 이 기록은 메모리에만 있어
컨테이너를 재시작하면 모든 잠금이 풀린다. IP는 nginx가 덮어써서 넘겨주므로 바깥에서
지어낼 수 없지만, LAN에서 백엔드 포트(8000)로 직접 들어오면 그 헤더를 마음대로 보낼 수
있어 제한을 우회할 수 있다.

계정을 지우면 그 사람의 폴더를 먼저 `deleted-users/<아이디>-<시각>/`으로 통째로 옮기고
그다음 계정 행을 지운다. `users/` **밖**으로 옮기는 이유는, 안에 남긴 이름이 가입 규칙을
통과하는 유효한 아이디라서 그 이름으로 가입하면 지워진 사람의 데이터를 물려받기
때문이다. 삭제가 "마지막 관리자"라 거절되면 옮긴 폴더를 제자리로 되돌린다.

### 문서

한 사용자의 문서는 `users/<아이디>/data/` 안에 **실제 파일과 실제 폴더로 그대로** 있다.
마크다운은 변환 없이 `.md` 파일 자체이고, 별도 DB나 인덱스가 없다. 서버를 꺼도 폴더를
열면 그대로 읽힌다.

같은 트리에서 이미지, PDF, 영상, 소리, 평문 파일도 함께 다룬다. 텍스트 계열만 편집기로
열리고 나머지는 전용 뷰어나 내려받기로 간다. 확장자 판정은 한 곳(`file_kinds`)에서만
하며, `2026.08 회고` 처럼 점이 들어간 제목을 확장자로 오해하지 않는다.

편집기는 타자가 멈춘 뒤 기본 900ms에 자동 저장한다. `Ctrl/Cmd+S`는 기다리지 않고 바로
저장한다. 저장이 실패하면 그 작업을 버리지 않고 들고 있다가 다음 기회에 다시 시도하며,
다른 문서를 열거나 이름을 바꾸거나 옮기기 전에는 대기 중인 저장을 먼저 흘려보내고
그것이 실패하면 그 동작 자체를 중단한다. 아직 서버에 없는 마지막 문단이 옛 경로와 함께
사라지지 않게 하기 위해서다. 반대로 문서를 삭제할 때는 대기 중인 저장을 취소한다 —
취소하지 않으면 타이머가 방금 지운 문서를 다시 만들어 낸다.

서버 저장은 같은 프로세스 안의 경로별 잠금 아래에서 같은 폴더의 임시 파일에 쓰고 `fsync`
후 `os.replace`로 갈아 끼운다. 쓰다 만 파일이 남지 않고, 줄바꿈은 쓴 그대로 보존된다.

`[[제목]]`, `[[제목|별칭]]`, `[[제목#섹션]]`이 링크로 해석된다. 대상은 확장자를 뗀
파일명으로 대소문자 구분 없이 `.md` 중에서 찾는다. `![[사진.png]]`는 링크가 아니라 그림
임베드다. 코드 울타리·인라인 코드·들여쓴 코드블록 안의 링크는 세지 않으며, 목록 안
4칸 들여쓰기는 코드가 아니라 하위 항목으로 본다. 이 규칙은 그래프와 화면이 **같은
답을 내도록** 양쪽에 맞춰져 있다.

백링크는 저장해 두지 않는다. 문서를 열 때 그때그때 그래프를 만들어 그 문서를 가리키는
것만 골라 준다. 그래프는 서버 메모리에 캐시하고 파일 개수·크기·수정시각·**이름 목록의
해시**로 무효화한다. 이름 해시를 넣은 이유는 이름 변경과 이동이 나머지 값을 하나도
바꾸지 않아서, 그것만 보면 그래프가 낡은 채로 남기 때문이다.

읽기 뷰의 위키링크를 눌렀을 때 대상이 없고 확장자도 없는 제목이면 `# 제목` 한 줄이 든
문서를 **문서 루트에** 만든다. 편집기 슬래시 메뉴의 "새 문서 만들어 링크"만 지금 폴더에
만든다. 확장자가 붙은 이름은 만들지 않고 "찾을 수 없음"만 알린다.

### 캘린더

일정은 기본적으로 `users/<아이디>/calendar/events.json`에 JSON 배열로 저장된다. 시각은
타임존 없는 `YYYY-MM-DDTHH:MM:SS`이고 종일 일정은 `YYYY-MM-DD`이며 종료일은 마지막 날을
포함한다.

**반복 일정은 회차를 따로 저장하지 않는다.** 원본 한 건에 반복 규칙(daily/weekly/monthly/
yearly), 간격, 종료일, 예외 날짜만 적어 두고 조회할 때 요청한 기간 안의 회차로 펼친다.
펼쳐진 회차의 id는 `<원본id>@<날짜>` 형식이고, 회차의 끝은 "그 날짜 + 원본 길이"로
계산하므로 자정을 넘기는 반복도 길이가 유지된다.

반복 일정의 **한 회차만 시간을 옮기면** 그 날짜가 원본의 예외 목록에 들어가고, 반복 없는
단발 일정이 새로 만들어진다. 떼어낸 쪽에 원본 id가 `split_from`으로 붙어 어디서 나왔는지
남는다. 원본 시작일은 건드리지 않는다. 반대로 회차 id로 오되 시각은 그대로인 수정(제목·색
만)은 시리즈 전체에 적용된다 — 그래야 시리즈 시작일이 그 회차 날짜로 밀려 이전 회차가
통째로 사라지지 않는다. 시리즈를 통째로 지우면 떼어냈던 회차들도 함께 지워지고, 지우기
전에 그것들까지 휴지통에 담는다(이 보완은 내부 캘린더에서만 동작한다).

Google Calendar를 연동하면 목록·생성·수정·삭제가 전부 Google API로 가고 그 계정의
`events.json`은 읽지도 쓰지도 않는다. 연동을 끊으면 내부 파일에 있던 예전 일정이 그대로
다시 보인다. 여러 건을 다룰 때는 배치 요청으로 50건씩 묶고, 배치가 막히면 한 건씩 순차
재시도한다. 연동 시작은 주인만 할 수 있고 해제는 본인이면 누구나 할 수 있다.

알림은 서버가 밀어 주지 않는다. 로그인한 브라우저가 30초마다 다가오는 일정을 물어보고,
알림 시각이 지났고 아직 시작 전인 것을 브라우저 알림이나 화면 토스트로 띄운다. 이미 띄운
회차는 브라우저에 기록해 다시 띄우지 않는다. 이 알림은 내부 캘린더 전용이며, Google 연동
계정에서는 Google이 자기 알림으로 알려 준다.

색은 Google 팔레트와 같은 11색이고 `1`~`11` 숫자로만 저장된다. AI에게 말로 색을 지정하면
한국어 이름과 별칭으로 찾아 주고, 못 알아들으면 기본색으로 바꿔치기하지 않고 실패로
답한다.

#### 기록 (상태·일기)

달력 툴바의 **기록** 버튼을 켜면 달력이 월 보기로 고정되고 일정 대신 그날의 상태 도형만
보이며, 오른쪽 AI 패널 자리에 그날의 기록 패널이 들어온다. 날짜를 누르면 패널이 그
날짜로 바뀐다.

상태는 **육체·마음·정신** 세 축을 따로 적고, 축마다 다섯 도형 중 하나를 고른다 —
별(매우 좋음)·동그라미(좋음)·세모(보통)·네모(힘듦)·오각형(매우 힘듦). 고른 도형만
강조색이고 나머지는 회색이며, 같은 도형을 다시 누르면 지워진다. 달력 칸에는 도형 세 개만
`육체 마음 정신` 순서로 그려지고, 안 고른 축은 `-`로 나온다(마음만 비우면 `○ - ○`). 세
축 다 비어 있으면 칸에 아무것도 없다(일기만 있으면 작은 점 하나).

패널 아래에는 날짜와 **그날 일정 목록**이 자동으로 채워지고(내부 캘린더든 Google이든
화면에 보이는 일정 그대로), 그 밑이 일기다. 사용자가 손대는 것은 도형과 일기뿐이다.
도형은 누르는 즉시, 일기는 문서와 같은 자동 저장 지연으로 저장된다.

저장은 `users/<아이디>/diary/diary.json` 한 파일이고 날짜별로 `{body, heart, mind, text}`
가 들어간다. 도형 셋과 일기가 전부 비면 그 날짜 항목 자체를 지운다. 기록은 Google로
나가지 않고 휴지통에도 들어가지 않는다(지우는 동작이 없고 비우는 것뿐이다).

### 할 일

`users/<아이디>/todo/todo.json` 한 파일에 카테고리와 할 일이 함께 들어간다. 카테고리만
지웠는데 할 일이 어긋나는 일을 막으려고 한 번의 원자적 쓰기로 같이 갱신한다.

카테고리는 폴더처럼 중첩된다(새로 만들 때 5단계까지). 카테고리를 지정해 조회하면 그
카테고리와 **모든 하위 카테고리**의 할 일이 함께 나온다. 카테고리를 지우면 그 안의 할
일과 하위 카테고리는 삭제되지 않고 한 단계 위로 올라간다.

마감은 날짜만 주면 종일, 시각까지 주면 시각 지정으로 자동 판단한다. 마감이 있는 할 일은
캘린더 화면의 "할 일" 보기에서 읽기 전용으로 볼 수 있다. 일정과 할 일은 같은 달력에
섞이지 않고 툴바 버튼으로 갈아 낀다.

**할 일은 Google로 나가지 않는다.** 캘린더 화면에 보이더라도 이 서버가 자기 저장소에서
읽어 그린 것이고, Google 계정을 연결해도 마찬가지다.

한 사용자당 할 일 5000개, 카테고리 200개가 상한이다.

### 휴지통

문서(파일·폴더), 캘린더 일정, 할 일, 단어장의 단어, 논문, 회의 여섯 갈래가 들어간다.
`users/<아이디>/.trash/` 아래에 목록 파일과 실물을 함께 보관하며, 문서 루트의 형제
폴더라서 문서 목록·검색·그래프에는 나타나지 않는다.

문서는 실물 파일이 그대로 옮겨지고, 논문은 PDF·추출 정보·그 논문에서 나눈 AI 대화가 든
폴더째, 회의는 녹음·받아쓰기·정리 문서·대화가 든 폴더째 옮겨진다. 일정·할 일·단어는
파일이 아니므로 내용 스냅샷으로 적힌다.
실물 이동과 목록 기록을 같은 잠금 안에서 처리하고 목록에 싣지 못하면 실물을 제자리로
되돌리므로, 목록에 없는 미아 파일이 남지 않는다.

복원은 **절대 덮어쓰지 않는다.** 원래 자리에 이미 뭔가 있으면 `이름 (restored).확장자`로
옆에 만든다. 일정 복원은 파일을 되돌리는 게 아니라 캘린더에 새로 만드는 것이라 id가
바뀌고, 할 일은 원래 id를 그대로 되살린다. 단어는 태그·복습 상태째 돌아오되 그새 같은
표제어를 다시 넣었다면 그 단어에 합쳐진다. 논문과 회의는 폴더가 제자리로 돌아가므로
대화도 같이 살아난다.

**자동으로 비워지지 않는다.** 보관 기간이나 정리 스케줄러가 없다. 직접 영구 삭제하거나
비우기를 눌러야 없어지고, 그전까지 디스크 용량을 차지한다. 영구 삭제와 비우기는 둘 다
확인 창을 거친다.

휴지통은 사용자별이고 API는 항상 세션 사용자 것만 본다. 주인이라도 다른 사람 휴지통은
볼 수 없다.

### AI 비서

Google Gemini를 쓰는 ReAct 방식 에이전트다. 왼쪽 메뉴의 전용 페이지, 캘린더 화면 오른쪽
패널, 영어 학습 화면, 논문 화면, 회의 화면 다섯 곳에서 같은 채팅 UI를 쓴다.

동작은 이렇다. 모델을 호출해서 도구 호출이 나오면 그 스킬들을 실행하고 결과를 대화에 붙여
다시 호출한다. 텍스트만 나오면 그때 끝낸다. 최대 단계는 계정별 설정(1~16, 기본 8)이고
한도에 닿으면 지금까지 실행한 목록과 함께 중단됐다고 반드시 알린다.

스킬은 **52개**다.

| 갈래 | 개수 | 내용 |
|---|---|---|
| 문서 | 11 | 목록, 폴더 목록, 읽기, 검색, 쓰기, 덧붙이기, 삭제, 이름변경, 이동, 폴더 생성, 백링크 |
| 캘린더 | 8 | 조회, 생성, 수정, 삭제, 빈 시간 찾기, 일괄 생성/수정/삭제 |
| 할 일 | 9 | 조회, 카테고리 조회, 생성, 수정, 완료, 삭제, 일괄 완료/삭제, 카테고리 생성 |
| 단어장 | 6 | 조회, 태그 조회, 추가, 후보 제안, 수정, 삭제 |
| 논문 | 5 | 목록, 정보, 본문 읽기, 지난 대화 검색, 메모 |
| 회의 | 9 | 목록, 정보, 받아쓰기 읽기, 문서 목록/읽기/쓰기/덧붙이기/삭제, 정보 수정(제목·화자 이름 등) |
| 휴지통 | 2 | 목록, 복원 |
| 기타 | 2 | 생각 정리, 시스템 상태(주인 전용) |

비서 화면은 스킬 전부를 쓰고, 영어 학습·논문·회의 화면은 **모드**(`english`, `paper`,
`meeting`)를 붙여 보낸다. 모드는 그 화면에 맞는 시스템 프롬프트와 스킬 부분집합만 준다 —
영어 학습에는 캘린더 스킬이 없고, 논문 모드에만 논문 스킬이, 회의 모드에만 회의 스킬이
있다. 스킬이 적을수록 모델이 엉뚱한 도구를 고르지 않는다.

응답은 SSE로 흘러온다. 스킬이 시작되면 회색 칩이 뜨고 결과가 오면 성공·실패로 바뀐다.
다만 **답변 본문은 토큰 단위로 흐르지 않고** 맨 마지막에 통째로 도착한다.

모든 스킬은 세션 사용자로 만든 컨텍스트만 받고, 경로가 전부 그 사용자 폴더 아래로만
풀린다. 스킬 인자에 사용자를 지정하는 항목 자체가 없다. 이름에 비밀·계좌·password·`.env`
같은 조각이 든 문서는 본문을 읽지 못한다. 시스템 프롬프트는 문서 본문이나 일정 제목을
데이터로만 취급하고 그 안의 지시는 따르지 말라고 명시한다 — 모델에 대한 지시이지 강제
차단은 아니므로, 실제로 막아 주는 것은 위의 이름 기반 차단과 사용자 격리다.

AI가 지운 것은 전부 휴지통으로 간다. 영구 삭제·비우기 스킬은 되돌릴 수 없어서 일부러
만들지 않았다.

비서·캘린더 화면의 대화는 서버에 저장되지 않는다. 브라우저가 지금까지의 말풍선을 매 요청
다시 보내고, 서버는 최근 20턴·총 24000자로 잘라 받는다. 영어 학습·논문·회의 화면은 반대로
서버에 남긴다(아래 참고) — 브라우저는 보내지 않고 서버가 저장된 기록에서 같은 한도만큼
꺼내 넣는다. 어느 쪽이든 이전 스킬 결과(조회로 얻은 id 등)는 모델에 다시 들어가지
않으므로 "확인했어, 그거 지워줘" 같은 두 차례 작업은 매번 다시 조회한다.

**예약 실행은 없다.** 대화가 끝나면 아무것도 돌지 않는다.

API 키가 없으면 채팅창 위에 안내 배너가 뜨고, 메시지를 보내면 키가 없다는 답이 온다.
나머지 기능은 정상 동작한다.

### 영어 학습과 단어장

왼쪽이 AI 튜터 채팅, 오른쪽이 단어장이다. 튜터는 단어를 보내면 뜻·비슷한 단어(↔ 반대)·
영어 해설·예문(영문 → 해석, 문법 포인트)·동사/품사 변화·포인트 순으로 설명하고, 문장을
보내면 해석·문장 구조·핵심 단어로 풀어 준다. 설명이 끝나면 `propose_vocab_words`로
어려운 단어를 후보로 올리고, 채팅창에 **체크 목록**이 떠서 고른 것만 단어장에 들어간다.
"넣어줘"라고 분명히 말하면 바로 `add_vocab_words`로 사전 내용을 전부 채워 넣는다.

단어장은 계정당 파일 하나(`vocab/vocab.json`)이고, 영어 학습 화면과 논문 화면이 같은
단어장을 본다. 단어는 **어디서 가져왔는지**를 태그로 구분한다 — 논문 제목, "일상 대화",
"TOEIC" 같은 자유 문자열이다. 태그 목록은 따로 저장하지 않고 단어에서 모은다. 같은
표제어를 다시 넣으면 새로 만들지 않고 **합친다**: 태그와 문맥은 더하고 설명은 더 긴 쪽을
남긴다. 그래서 논문 두 편에서 만난 단어에는 태그가 둘 다 붙는다.

단어장 패널에서는 태그 칩으로 걸러 보고(태그 이름으로 칩을 찾는 검색이 따로 있다),
단어·뜻·유사어로 검색하고, 최근·가나다·복습순으로 정렬한다. 단어를 누르면 위 형식
그대로 펼쳐지고, 손으로 추가·수정하거나 태그 이름을 한꺼번에 바꿀 수 있다.

**복습**은 간격 반복이다. 단어마다 레벨(0~7)이 있고 맞히면 한 단계 올라 1·3·7·14·30·60·
120일 뒤에 다시 나오며, 틀리면 두 단계 내려가 내일 다시 나온다. 새 단어와 기한이 지난
단어가 "오늘 복습"에 잡히고, 복습 버튼은 플래시카드(앞면 단어 → 뒷면 뜻·해설·예문)로
한 번에 20개까지 돌린다. 튜터에게 "오늘 복습할 거 퀴즈 내 줘"라고 해도 된다 — 같은
큐를 `list_vocab(due_only)`로 가져와 한 문제씩 낸다.

이 화면의 대화는 서버에 남는다(`chats/english.json`, 최근 600개). 새로고침해도 이어지고,
"지난주에 물어본 단어"가 다음 대화의 맥락이 된다. 상단의 "대화 비우기"로 지운다.

### 논문

왼쪽이 논문 목록, 가운데가 PDF, 오른쪽이 AI 채팅·정보·단어장 탭이다. PDF는 목록에 끌어다
놓거나 골라서 올리고(여러 개 한꺼번에, 100MB까지, `%PDF` 머리글이 없으면 거절), 논문마다
`papers/<id>/` 폴더에 원본·추출 본문·그 논문에서 나눈 대화가 함께 산다.

올리면 **백그라운드에서 정보 추출**이 한 번 돈다. pypdf로 쪽수와 본문을 뽑아 `text.txt`에
두고, Gemini에 PDF(18MB 이하면 원본, 크면 본문 앞 6만 자)를 주어 제목·저자·연도·출처·
초록·요약·핵심 발견·방법·한계·키워드·목차를 JSON으로 받아 메타에 적는다. 그동안 목록에는
"정보 추출 중"이 돌고 화면이 4초마다 다시 물어본다. 실패하면 `failed`로 남고 메뉴에서
다시 시킬 수 있다. 서버가 재시작돼 `pending`인 채 남은 것은 다음 목록 조회 때 다시 큐에
들어간다. API 키가 없으면 추출은 실패하지만 PDF 보기와 대화는 된다.

PDF는 브라우저에서 pdf.js로 그린다. 보이는 쪽 근처만 렌더하고, 배율은 폭 맞춤 또는
50~300%, 마지막으로 읽던 쪽을 기억해 다음에 열 때 거기서 시작한다. 도구는 둘이다.

- **텍스트** — 글을 드래그하면 "AI에 넣기 / 설명 / 영어" 팝오버가 뜬다. "AI에 넣기"는
  선택한 글을 채팅 입력 위의 문맥 칩에 쌓고, 나머지 둘은 설명·해석 요청을 바로 보낸다.
- **영역** — 그림·표·수식을 사각형으로 드래그하면 그 부분을 캔버스에서 잘라 PNG로 칩에
  쌓는다. 여러 쪽에서 여러 개 모을 수 있고, 칩마다 X, 도구 모음에 "선택 지우기"가 있다.

칩은 다음 메시지와 함께 간다(이미지 8장·장당 3MB, 글 12개). 이미지는 Gemini가 직접 읽어
그림·표·수식을 해석한다. 서버는 대화 기록에 **이미지를 남기지 않고** 라벨만 적는다.

AI는 지금 보는 논문의 추출 정보와 내 메모, 다른 논문들의 제목·요약 한 줄을 시스템
프롬프트로 받고, 이 논문의 최근 대화(20턴·24000자)를 앞에 둔다. 본문 근거가 필요하면
`read_paper_text`로 쪽 범위나 검색어로 읽어 **쪽수를 함께** 말하고, "전에 물어봤던"이
나오면 `search_paper_chats`로 모든 논문의 지난 대화를 뒤진다. "메모해 둬"는
`set_paper_notes`, "다음 주까지 읽기"는 할 일, 발표 시각은 캘린더 일정으로 넘긴다.

영어 질문을 하면 영어 학습 화면과 같은 형식으로 답한 뒤 "단어장에 넣을까요?" 체크
목록을 띄운다. 이 화면에서 넣는 단어에는 **논문 제목이 태그로 자동으로 붙어서**, 단어장
탭이 그 태그로 걸러진 채 열린다. 정보 탭에서는 제목을 고치고 별표를 달고, 요약·핵심
발견·방법·한계·초록을 읽고 내 메모를 적는다. 키워드와 목차 항목은 누르면 그 대목에
대해 바로 묻는 버튼이고, 위에 "3줄 요약·핵심 기여·방법 설명·한계·어려운 단어" 같은
빠른 질문 칩이 있다.

논문을 지우면 폴더째 휴지통으로 가고 대화도 함께 돌아온다.

### 회의 녹음

왼쪽이 회의 목록, 가운데가 녹음·원본·정리 문서, 오른쪽이 AI 회의 비서다. 녹음은 두
길이다 — **녹음** 버튼은 브라우저 마이크로 바로 녹음해서(MediaRecorder, webm/mp4)
저장하고, **올리기**는 mp3·m4a·wav·webm·ogg·flac·aac 파일을 끌어다 놓거나 골라 올린다
(한 건 300MB까지). 올릴 때 제목·카테고리·날짜를 적을 수 있고 비우면 파일 이름과 오늘
날짜가 들어간다. 회의마다 `meetings/<id>/` 폴더에 원본·받아쓰기·정리 문서·그 회의에서
나눈 대화가 함께 산다. **원본 녹음은 절대 손대지 않는다.**

목록은 날짜별로 묶이고 카테고리 칩으로 거른다. 제목·날짜·카테고리는 가운데 머리글에서
바로 고친다.

올리면 **백그라운드에서 받아쓰기**가 한 번 돈다. Gemini에 녹음을 그대로 들려 주고(18MB
이하면 인라인, 크면 Files API로 올린 뒤) 구간마다 시각·화자·문장을 JSON으로 받아
`transcript.json`에 두고, 3~5문장 요약을 메타에 적는다. **화자 구분**은 모델이 목소리로
짐작한 "화자 1/화자 2" 라벨이다 — 화면에서 라벨을 눌러 이름을 붙이면(또는 비서에게
"화자 1은 김철수야") 원본 위와 AI가 읽는 받아쓰기에 그 이름이 붙는다. 진행 중이면
목록에 "받아쓰기 중"이 돌고 화면이 4초마다 다시 물어본다. 실패하면 `failed`로 남고
"다시 받아쓰기"로 다시 시킨다. 서버가 재시작돼 `pending`인 채 남은 것은 다음 목록
조회 때 다시 큐에 들어간다. API 키가 없으면 받아쓰기는 실패하지만 녹음 재생과 문서
편집은 된다.

원본 탭은 구간마다 `[mm:ss]`가 붙어 있고 누르면 위 재생기가 그 시각으로 간다. **정리
문서**는 회의 폴더 안의 `docs/<이름>.md`이고, 문서 화면과 같은 편집기(위키링크·슬래시
메뉴·자동 저장)를 쓰지만 **저장소는 문서 트리와 분리**돼 있어 문서 목록·그래프·검색에
나오지 않는다. 회의당 100개, 문서당 40만 자가 상한이다.

AI 비서는 지금 보는 회의의 정보와 자동 요약, 화자 이름, 다른 회의들의 제목 한 줄을 시스템
프롬프트로 받는다. "회의록 만들어 줘", "결정 사항만 짧게", "액션 아이템을 담당자별로"처럼
원하는 느낌을 말하면 `read_meeting_transcript`로 원본을 읽고(길면 이어 읽기)
`write_meeting_doc`으로 그 회의 공간에 문서를 만든다. 만든 문서는 곧바로 탭에 떠서 손으로
이어 고치면 된다. 이 화면의 대화는 `meetings/<id>/chat.json`에 남는다.

회의를 지우면 폴더째 휴지통으로 가고 복원하면 대화까지 함께 돌아온다.

### 설정

계정마다 `users/<아이디>/settings.json`에 다섯 묶음이 저장된다.

| 묶음 | 항목 |
|---|---|
| ai | 말투(상담사/비서/친구), 모델, 최대 추론 단계 |
| calendar | 기본 색, 기본 보기, 주 시작 요일, AI 기본 알림, AI 규칙 |
| notes | 자동 저장 지연, 삭제 확인 |
| display | 타이머 초 표시 |
| security | 자동 로그아웃 분 |

바꾼 항목만 서버로 보내면 나머지는 유지된다. 허용 범위를 벗어난 숫자는 범위 끝으로
잘리고, 정해진 목록에 없는 값은 기본값으로 되돌아간다. 자유 입력 글이 2000자를 넘으면
**조용히 자르지 않고 저장을 거절한다.** 반대로 읽을 때는 자르지 않는다 — 상한이 생기기
전에 길게 써 둔 글이 다른 설정 하나 바꿨다고 사라지면 안 되기 때문이다.

없어진 기능이 남긴 설정과 모르는 항목은 저장 시점에 파일에서 지워진다.

### 시스템 모니터

대시보드 첫 카드에서 CPU 사용률과 코어 수, 메모리, CPU 온도, 디스크 사용량, 가동 시간을
보여준다. 2.5초마다 다시 물어보고 브라우저 탭이 가려져 있으면 건너뛴다. 디스크 수치는
사용자 파일이 저장되는 저장소 기준이다. 온도는 리눅스 센서에서 읽으므로 개발용 Windows
에서는 대개 표시되지 않는다.

주인만 볼 수 있다. 화면을 숨기는 것이 아니라 API 자체가 주인 전용이다.

### 웹 터미널 (선택, 기본 꺼짐)

브라우저에서 라즈베리파이 **호스트의 루트 셸**을 쓰는 화면이다. 셸을 띄우는 쪽은
백엔드가 아니라 별도 컨테이너이고, 그 컨테이너는 호스트의 프로세스 네임스페이스를
공유하고 권한 제한 없이 돌기 때문에 컨테이너 안이 아니라 파이 본체에 명령이 그대로
적용된다.

기본은 꺼져 있다. 켜려면 `.env`에 `ENABLE_TERMINAL=true`를 넣고
`docker compose --profile terminal up -d --build`로 올려야 한다.

화면에 보이는 조건은 "환경변수로 켜져 있음"과 "주인이면서 `TERMINAL_ADMINS` 목록에 있음"
둘 다이다. 실제 권한 경계는 터미널 컨테이너 쪽이며, 웹소켓 접속의 세션 쿠키를 백엔드와
같은 키로 검증하고 계정 파일에서 그 계정이 주인인지 다시 확인한다. 이름만 같은 가입
계정은 거부된다. 접속한 뒤에도 60초마다 다시 확인해서 세션이 만료됐거나 계정이
비활성·강등되면 열려 있던 셸을 끊는다.

**켜기 전에 주인 계정 비밀번호를 반드시 강하게 설정해야 한다.** 이 조건을 만족하는 계정
하나가 곧 서버 전체다.

### 외부 SSH 접속 (선택)

집 밖에서 파이에 SSH로 들어오는 길이다. 공유기 포트를 열지 않는다 — 이미 돌고 있는
Cloudflare Tunnel(`--profile tunnel`)이 밖으로 연결만 유지하고, 그 터널에 SSH용 공개
호스트 이름을 하나 더 얹는다. `cloudflared` 컨테이너에는
`extra_hosts: host.docker.internal:host-gateway`가 붙어 있어 컨테이너에서 파이 본체의
22번에 닿는다.

1. Cloudflare 대시보드 → Zero Trust → Networks → Tunnels → 이 터널 → **Public Hostname**
   추가: `ssh.<도메인>` → 서비스 `ssh://host.docker.internal:22`.
2. `.env`에 `SSH_PUBLIC_HOSTNAME=ssh.<도메인>`, `SSH_USER=<파이 계정>`을 적고 백엔드를
   다시 띄운다. 대시보드 맨 아래 **외부 SSH 접속** 카드에 클라이언트 설정이 뜬다.
3. 클라이언트 PC에 `cloudflared`를 설치하고 `~/.ssh/config`에 카드의 내용을 넣는다.

```
Host ssh.<도메인>
    ProxyCommand cloudflared access ssh --hostname %h
    User <파이 계정>
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

그 뒤로는 `ssh ssh.<도메인>`이면 된다. 인증은 파이의 sshd가 그대로 하므로 **비밀번호
로그인은 끄고 키만 받도록** 해 두는 편이 안전하다. 서버 쪽 코드가 하는 일은 안내를
보여 주는 것뿐이고(`/api/system/ssh`, 주인 전용), 접속 자체에는 관여하지 않는다.

## 저장 구조

```
STORAGE_ROOT/
  accounts.json                  계정 목록 (단일 출처)
  deleted-users/                 삭제된 계정의 데이터
  users/<아이디>/
    data/                        문서 (실제 파일 트리)
    calendar/events.json         내부 캘린더
    diary/diary.json             날짜별 상태(육체/마음/정신)와 일기
    todo/todo.json               할 일과 카테고리
    vocab/vocab.json             단어장 (태그·복습 상태 포함)
    chats/english.json           영어 학습 화면의 AI 대화
    papers/index.json            논문 목록·추출 정보 (본문은 없다)
    papers/<id>/paper.pdf        원본 PDF
    papers/<id>/text.txt         pypdf 로 뽑은 본문 (AI 가 읽는다)
    papers/<id>/chat.json        그 논문에서 나눈 AI 대화
    meetings/index.json          회의 목록·요약·화자 이름
    meetings/<id>/audio.<ext>    원본 녹음 (손대지 않는다)
    meetings/<id>/transcript.json  받아쓰기 (구간별 시각·화자·문장)
    meetings/<id>/docs/*.md      정리 문서 (문서 트리와 별개)
    meetings/<id>/chat.json      그 회의에서 나눈 AI 대화
    .trash/                      휴지통 (index.json + data/)
    settings.json                개인 설정
    google.json                  Google 연동 토큰
```

JSON 저장은 전부 같은 폴더의 임시 파일에 쓴 뒤 `os.replace`로 갈아 끼운다. 파일이 깨져
있으면 빈 값으로 보지 않고 503으로 거절한다 — 그래야 깨진 상태 위에 덮어써서 원본이
통째로 사라지지 않는다.

## 배포

`main`에 push하면 파이의 셀프호스티드 러너가 최신 코드로 컨테이너를 재빌드한다.
재빌드 전에 직전 이미지를 `twoems-prev:*`로 태그해 두고, 배포 후 헬스 체크가 실패하면
되돌리는 명령을 로그에 남긴다.

수동 실행은 `bash scripts/deploy.sh`.

자세한 설정은 [docs/auto-deploy.md](docs/auto-deploy.md), 작업 내역은
[docs/REPORT.md](docs/REPORT.md) 참고.
